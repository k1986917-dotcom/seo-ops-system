# ADR-0021：多来源任务卡种子与忠实包装

- 状态：已接受
- 日期：2026-07-18
- 规则：`multi_source_topic_research 0.12.0`、`topic-hypothesis 0.10.2`、`candidate_qualification 1.1.3`
- 证据等级：C（程序推断）+ E（公开第三方语言/竞品问题）+ 隔离真实外部测试
- 复查日期：2026-10-17

## 背景

`0.10.6` 已取消范围、需求和材料的发现期硬门，并把旧 Plan 的问题链接入调研；但宽泛“分支 + 问题词”种子仍反复返回泛问题、相邻产品噪声或已覆盖主题。运营者要求的验收不是偶尔出现一个好角度，而是每次调研稳定产生至少一个不与现有正文重复的新主题，且不能靠放松去重或编造主题达成。

旧 Plan 实际优势不是其通用搜索字符串，而是先从集群缺口、痛点、公开讨论和角色前沿中选一个未覆盖方向，再让 AI 将它包装成具体任务。

## 决策

1. 将旧 Plan 的前沿选择表达成版本化的任务卡：`角色 × 单一任务 × 条件`，并保存 `source_type` 与 `source_basis`。
2. 任务卡只能是计划假设：公开第三方痛点、竞品问题、集群缺口和角色前沿均不构成本站需求、第一方反馈、角色真实使用或可直接成稿的事实。
3. 每次主题/边界调研优先按来源多样性选择至多三个未尝试卡。若某细分分支只有一两张卡，精确卡仍排在首位，剩余预算由旧 Plan 的独立问题链补足；自动入口优先仍有未尝试卡的主题分支和维度；卡耗尽后回退到既有自然假设或旧 Plan 问题链。
4. 外部调用前只用当前 CMS 的主意图、H2 和正文做重复预筛。只有 `same_intent` 或 `covered_subtopic` 的卡不消耗预算；不以范围、意图表达、需求、材料或信号强弱排除卡。
5. 将选中的卡及预筛关系写入 `research_runs.filters_json`，并传给 AI。AI 只能忠实保持卡里的角色、任务和条件；不能把画面表现扩展成相机损坏、把连续使用需求扩展成改装方案，或增加未被卡片/证据支持的风险、测量、用途、替代产品或法律主张。证据无法忠实支持时允许不输出主题。
6. 候选资格继续是纯重复判定。明确换成激光水平仪、旋转激光、切割机等相邻核心产品只作为软优先级诊断，绝不恢复为资格硬门。

## 隔离实测

所有测试复制生产 SQLite、保留 CMS/GSC 输入、清除或隔离派生研究状态；每次生产数据库 SHA-256 前后相同。

- 10 个单种子真实对照中，8 个产生至少一个不重复的 AI 成型主题。两个失败分别暴露了正确的正文重复路由（焦环）和宽泛冷凝词的检索噪声。
- 三个“每轮三个不同来源种子”的真实批次分别产生 `1`、`2`、`1` 个独立成型主题。
- 自动任务池原型仅依据旧 Plan 已登记的公开痛点、竞品问题、集群缺口和角色前沿生成 28 个搜索假设；CMS 重复预筛保留 14 个、拦截 14 个。其后三个自动批次分别产生 `3`、`2`、`3` 个独立成型主题。
- 加入忠实度约束的真实批次产生建筑检查中的远处缺陷指示、相机/TV 中绿点过亮或 bloom、以及手持激光笔在占空比约束下是否适合连续对准三个主题；未再出现“相机损坏”或“改装”这种未支持扩展。
- 大多数 SerpAPI、Tavily、AI 调用成功；少量 Firecrawl 页面采集失败如实保留为 `partial`，不被当作成功或需求证据。
- 正式接入后，再以每轮各一次 SerpAPI、Tavily、Firecrawl 与 AI 做三轮隔离复测。三轮均为 `success`，且分别得到树艺师从地面指示修枝位置、Laser 303 模式跳变/变暗症状诊断、相机/TV 中绿点过亮或 bloom 三个 `qualified/new_article` 成型主题；每轮保存了任务卡及 CMS 重复预筛。生产库 SHA-256 在三轮前后相同。

## 后果

- 预期效果是提高每轮发现的新主题密度与任务特异性，而不是承诺在真实市场已经饱和时无限生成可发布文章。
- 任务卡本身不会提升需求置信度或写作准备度；这些仍由本轮 SERP、页面材料、官方来源和人工审核承担。
- 原始 PAA/Related/Tavily 线索继续独立显示，不能因为任务卡存在而直接变成文章建议。
- 若卡耗尽、CMS 新增或真实复验持续无法得到独立主题，应补充新的可追溯前沿卡或如实报告不足；不得降低重复预筛、制造主题或自动发布。
