# ADR-0024：Hermes 托管 Legacy Research + Write 流水线

- 状态：Accepted
- 日期：2026-07-29
- 适用范围：Hermes 与新文章 Legacy R0→W3 制作通道的 HTTP 集成

## 背景

Legacy Research + Write 的内容规则、证据账本和阶段 gate 已由 SEO Ops 服务
实现，但 Hermes 只能逐个调用阶段脚本。这样会把阶段选择、失败恢复和资料不足时的
判断重新交给操作者，违背“用户只提供站点、选题和要求；Hermes 汇报结果”的目标。

同时，自动搜索凭据不一定存在。系统不得把提示词、AI 摘要或既有资料伪造成新的
外部搜索结果，也不能因为方便而绕过 W1b/W2/W3 的严格检查。

## 决定

1. SEO Ops 服务新增 Hermes 总控制器，顺序执行
   `R0 → 外部搜索/R1 → R3 → W0 → W1b → W2 → W3`。Hermes 只通过 HTTP 调用
   `start`、`continue`、状态和资料摘要接口；不写 SQLite、草稿或工作区。
2. 有 SerpAPI/Tavily 成功结果时，服务把不可变 provider 快照适配为 Legacy R1 输入，
   然后继续自动执行后续阶段。
3. 没有自动搜索结果时，服务停在持久的 `r0_prompt`，返回 R0 提示词和已同步资料
   摘要。Hermes 必须询问运营者选择：
   - 使用已有资料继续；或
   - 粘贴原样人工搜索结果。

   选择前不得继续，选择“已有资料”时输入必须明确标识其来源，不能冒充外部检索。
4. W1b 或 W2 失败时，一次明确继续最多执行两轮
   `AI 修订 → 必要复检`；通过立即继续。两轮仍失败即返回持久暂停。下一次明确继续
   才开启新批次，且把近期失败摘要与草稿 SHA 带入 AI prompt。
5. W1b 失败绝不进入 W2；W2 修订后必须再通过 W1b；W3 仍要求当前草稿的
   `gate_passed + applied + applied_draft_sha256`。人工确认仅保留原有的蚕食误报
   `--force` 条件，不能放行事实、证据、评分或检查器失败。
6. 网页人工模式继续保留，并在每个已开始阶段显示当前 action 的 R0 重启入口。

## 后果

用户不需要复制阶段按钮、手动编辑工作区或让 Hermes 猜测状态；意外中断后可从
action 的 DB stage 和持久文件恢复。无搜索凭据时仍有一个明确、人可审查的选择点。

这不证明 Hermes 写出的真实文章和旧人工流程 100% 等价。两者继续复用同一 Legacy
内容引擎；实际质量必须用相同真实主题和资料做对比验收。

## 失效与复查条件

- Legacy stage API 改为异步任务队列或更换状态存储。
- 真实运行显示“已有资料继续”经常无法产生可通过的 material pack。
- 连续批次频繁重复相同失败，说明失败记忆或提示词不足以改善结果。
- 真实对比显示 Hermes 编排造成研究资料丢失或文章质量显著下降。
