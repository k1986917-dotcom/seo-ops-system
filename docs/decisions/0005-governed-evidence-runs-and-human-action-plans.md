# ADR-0005：外部补证据按运行留痕，执行方案保持人工控制

- 状态：Accepted
- 日期：2026-07-14
- 部分替代：ADR-0009 已替代“新主题调研必须从明确 GSC 查询开始”的限制；本 ADR 的审计、缓存、证据边界和人工发布约束继续有效。

## 背景

0.2 已能安全配置和检测外部供应商，但“连接成功”不是证据。若分析时自动调用、只保存摘要或直接让外部结果改分，会产生不可审计费用、丢失原始口径，并把时点 SERP 错当成第一方事实。原有“接受”按钮也只创建一条行动记录，没有可执行步骤、顺序或取消机制。

## 决策

- 外部搜索只在运营者点击后执行，不随每次分析静默调用。
- 当前自动补证据只接受明确的 GSC 查询候选；页面标题不得被猜成查询。
- 每次运行记录 provider、purpose、输入 evidence ID、无密钥规范化参数、请求哈希、状态、用量、时间和安全错误。
- 响应先移除可能回显的凭据字节，再保存不可变快照、SHA-256 和大小；结构化 `evidence_items` 不能替代响应快照。
- 相同站点、provider、purpose 和参数哈希在 24 小时内复用成功快照，避免重复消费；该复用窗口登记在 `external_query_review 0.3.0`。
- SERP 与 Trends 只补充环境证据，不修改原 GSC 指标、机会强度、资格门槛或原候选分数。
- 新文章候选必须保留 GSC 查询事实、SERP 快照和 CMS 重叠推断的类型边界。缺少 query→page 联合数据和人工搜索意图复核时只能是 `needs_evidence`；SERP 已有本站结果或 CMS 强重叠时为 `blocked`。
- 接受非阻塞机会时冻结当时 evidence ID 和指标基线，并按 `action-plan-0.3.0` 生成有序步骤。后序步骤不能绕过前序，外部补证据步骤没有真实 SERP evidence ID 时也不能勾选完成；发布、删除和最终判断始终由运营者完成。

## 结果

SQLite v3 新增 `external_runs`、`evidence_items`、`action_steps`，并为 `actions` 增加工作流状态、方案版本和完成时间。外部失败可以局部保留成功快照，但不能成为证据；执行方案可以完成、重新打开、取消和恢复，不会自动调用 CMS。

当前限制是 query→page 定向导入尚未实现，因此新文章候选不会仅凭 SERP/Trends 自动过门槛。Firecrawl、Tavily、research brief 和 7/28/56 天测量仍是后续单元。
