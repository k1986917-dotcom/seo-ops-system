# ADR-0006：预算化多来源主题调研

- 状态：Accepted
- 日期：2026-07-14
- 部分替代：ADR-0009 已替代“新主题调研必须从明确 GSC 查询开始”的限制；本 ADR 的预算、审计、缓存、来源分工和引用校验继续有效。

## 背景

0.3 只支持针对单个明确 GSC 查询采集 SERP/Trends，尚未把 Firecrawl、Tavily 和 AI 组织为可控的完整主题调研。运营者希望主动使用多种 API 扩大发现范围，同时能为每轮分别限制调用量，避免静默消费、重复采集和 AI 脱离证据生成主题。

## 决策

- 外部主题调研只能由运营者显式触发，不能随页面加载或普通分析自动运行。
- 每轮分别保存 SerpAPI、Firecrawl、Tavily 和 AI 的预算、真实请求、成功、失败及复用次数。0.4.0 的默认值为 4/3/5/1，硬上限为 50/50/100/1；后续用户预算范围由 ADR-0009 更新。
- 相同站点、供应商、目的和规范化参数在 24 小时内复用成功快照。复用不算真实请求；剩余预算可以覆盖尚未采集的研究问题。
- SerpAPI 负责时点 SERP 与 Trends，Tavily 用于发现候选来源，Firecrawl 采集已经选定的公开页面，AI 只归纳本轮保存的证据。任何来源都不能越权证明其不能证明的结论。
- 单一供应商失败时保留其他成功证据并把运行标记为 `partial`，不能把失败、空结果或连接状态当作证据。
- SQLite v4 使用 `research_runs`、`research_run_items` 和 `research_candidates` 保存运行、证据关联与候选；当前实现每轮最多保存 8 个 `needs_evidence` 或 `blocked` 候选。
- AI 必须返回结构化 JSON 并引用本轮输入的完整 evidence ID。未知、歧义、伪造或无法解析的引用不进入候选事实。
- 外部研究不会重算 GSC 指标、机会强度或资格门槛；没有订单/GA4 时不输出收入或查询级转化结论。

## 后果

系统能够在可见预算内组合多个外部来源，并把快照、结构化证据、AI 输入输出和失败情况留作审计。连接数量不等于实际使用量，调用次数也不等于主题质量。

0.4.0 的种子仍局限于明确 GSC 查询，且候选不能直接进入机会。ADR-0009 后续把种子扩展为 GSC 信号、主题图谱缺口和边界扩展三类，同时保留本 ADR 的证据边界与成本控制。

真实测试曾使用 `deepseek-v4-flash` 完成受限结构化整理；模型成功返回 JSON 不代表候选已经通过意图、重复、站点边界或来源质量审核。正式文章素材包和 7/28/56 天效果观察由后续版本实现。
