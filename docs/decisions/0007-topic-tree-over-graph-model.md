# ADR-0007：树状界面、图结构底层的主题规划

- 状态：Accepted
- 日期：2026-07-15（2026-07-14 首次提案）

## 背景

站点已有 65 篇文章。单纯继续从查询或外部搜索生成标题，会反复发现相同意图，也无法说明某个方向是已覆盖、被拒绝、待证据还是暂时饱和。运营者希望从“激光笔 → 使用场景 → 钓鱼 → 具体用途”继续细化，并在主题下直接打开关联文章，同时保留可选人工介入。

纯树容易丢失一个主题与多个场景的关系；自由图编辑器又会把日常操作变复杂。

## 决定

1. 主界面使用可搜索、可折叠的树；每个规范主题只有一个主父级。
2. 底层保存图关系：跨分支使用 related，措辞变体保存为别名。
3. 主题树允许深浅不一，层级表达用户问题和页面职责，不机械表达关键词组合。
4. 文章通过显式关联挂到主题，标题作为可点击链接；自动映射保留依据和置信度。
5. 新发现先去重并检查边界；已确认边界内可进入资格判断，只有新受众、明显不同用途或站点目的变化才要求确认边界。
6. 历史决定是图谱的一部分，后续发现必须先检查，避免重复推荐。
7. 饱和按分支派生；没有合格项时允许等待新信号。
8. 分三阶段实现：只读树、待确认队列、可选人工操作，不从完整图编辑器起步。
9. 每篇文章保存一个主要文章主题和多个辅助知识主题，通用安全/功率/波长段落不主导重复判断。
10. 运营者主界面只显示“已有文章、值得扩展、暂无机会”，并只操作“要做、不再推荐、暂时跳过”；详细状态由系统派生。

## 后果

优点是运营者能直观看覆盖和方向，系统有稳定的主题身份和拒绝记忆，也能按分支研究。代价是需要新增可迁移数据表、初始文章映射和低置信人工复核。图谱不会保证存在 100–200 个值得发布的页面，资格和证据门槛继续优先。

## 方法依据

模型借鉴 W3C SKOS 的 broader、narrower、related 与别名关系。内容规模继续受 Google people-first 与 scaled content spam 边界约束；行业 topic cluster 只作为组织实践，不冒充 Google 排名机制。
