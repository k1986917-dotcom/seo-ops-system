# ADR-0008：每站点单一当前 GSC 分析批次

- 状态：Accepted
- 日期：2026-07-14（2026-07-15 修订物理删除边界）

## 背景

运营者确认旧导出在 2026-06-22 之前的数据不可信，并重新导入了 2026-06-22 至 2026-07-14 的 GSC 文件。原机会引擎会优先选择带 previous 周期的较旧对比导入，而数据质量服务选择最新导入，造成同一轮界面使用不同 GSC 批次。

原始导入默认不可变，但运营者进一步明确：若某次 GSC 导出本身因 Google 数据故障而没有参考价值，必须能够选中该批次并彻底删除，不能只在分析时隐藏。

## 决定

1. imports 使用两个独立派生状态：analysis_active 表示唯一当前机会批次，quality_eligible 表示可参与跨窗口稳定性判断的可信导入。
2. 每个站点只允许一个成功 GSC 导入处于当前分析状态；成功导入正常新文件时原子切换，并把新文件加入可信窗口，但不清除此前可信窗口。
3. 机会引擎和当前调研只使用同时满足 analysis_active=1 与 quality_eligible=1 的当前 GSC 批次；数据质量可以额外读取 quality_eligible=1 的历史窗口。
4. 原始导入默认不可变；只有运营者在导入记录上明确确认时，才允许逐条删除一个 GSC 批次。CMS 导入和批量清库不在该入口范围。
5. 删除会物理移除所选批次的原始快照、标准化指标、引用它的分析运行，以及只依赖这些分析的机会、行动、调研、外部证据与快照；不会删除其他 GSC 批次或 CMS 内容。
6. 删除当前批次后不自动恢复更旧批次。系统保持“无当前分析”，直到运营者重新导入正常 GSC 数据并运行分析。
7. 这次不把 2026-06-22 写成全局永久阈值；可信范围来自运营者对具体批次的判断。
8. 批次是否当前与数据是否充分是两件事。最新批次仍需经过观察窗口、异常和完整性门槛。

## 后果

正常导入仍保留幂等、快照和审计能力；真正错误的来源批次可被运营者彻底移除，避免以后再次污染分析。代价是该删除不可恢复，因此界面必须逐条操作、明确说明影响范围，并要求确认。删除后不自动回退旧数据，是为了避免刚移除的错误来源被另一个旧批次重新替代。
