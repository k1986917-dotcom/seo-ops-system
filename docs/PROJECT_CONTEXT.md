# 项目背景与真实约束

## 1. 为什么创建本项目

用户此前在 `/home/laoma/seo-workflow` 中使用三个 OpenCode Skill：

- `plan`：发现关键词/主题并推荐下一篇内容。
- `research`：调研并生成 material pack 与 brief。
- `write`：依据 material pack 写作、检查、注册。

该流程已经产生 65 篇文章和大量候选、brief、research data、material pack 与草稿。问题不是没有工作流，而是 `plan` 的选题进入瓶颈：数据被压缩、信号循环强化、合成关键词被当作需求、高蚕食只提示不拦截，反馈又只记录接受/拒绝而没有结果。

因此新项目不是关键词工具，也不是第四个独立 Skill。它是旧执行流程之上的控制平面：维护站点真实状态、判断该不该行动、选择行动、交付研究/写作任务，并在发布后复盘。
随着文章达到 65 篇，核心矛盾进一步变成主题身份和内容边界：系统需要知道哪些用户意图已覆盖、哪些只是同义表达、哪些被拒绝、哪个分支暂时饱和。主题图谱因此是机会发现之前的规划与记忆层，但不能变成要求运营者日常维护的复杂知识库。

运营者于 2026-07-15 确认两阶段业务流程：第一阶段“关键词与主题调研”联合内部数据、外部调研和主题图谱，最多交付 2 篇新文章与 2 篇旧文章建议；第二阶段“文章制作”对接受的建议完成素材、大纲、内外链、草稿/修改稿和自审，最终交付 CMS 字段。两阶段基础流程已在 0.5.0 上线。


## 2. 用户权限与可执行动作

用户目前能够：

- 查看和导出 GSC 数据。
- 新建、修改、删除文章。
- 修改产品页面。
- 决定内容主题。

不应默认用户能够：

- 修改服务器、模板、路由、robots、canonical 或站点代码。
- 配置 301 重定向。
- 获得订单、利润、GA4 或查询级转化数据。
- 自动向 CMS 发布。

所以机会引擎的默认动作空间是：

1. 更新文章标题/描述/正文/内链。
2. 更新产品页面文案。
3. 创建新文章。
4. 建议合并或删除，但在不能设置重定向时必须显示风险并要求人工确认。
5. 暂时不做。
6. 请求补充证据，例如页面筛选后的 GSC 查询导出。

## 3. 成功标准

系统成功不等于“生成了更多内容”。首要成功标准是：

- 推荐动作可执行、证据明确、风险可见。
- 能解释为什么现在做它，而不是另一个候选。
- 能区分事实、推断和经验默认值。
- 能发现更新现有页面比新建文章更好的情况。
- 做完后能观察并记录结果，逐步替换冷启动阈值。
- 单人每周能够实际完成，不产生管理负担。
