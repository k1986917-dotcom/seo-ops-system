# 两阶段内容工作流

状态：

- 第一阶段“关键词与主题调研”与第二阶段“文章制作”均已由运营者确认。
- `0.10.0` 保持五步顺序界面不变，并补上 GSC 只读 OAuth、查询—页面联合证据、英文候选去重、三类候选资格门和文章制作质量闸门。
- 外部调研和 AI 仍只在运营者点击后调用；发布、删除内容和最终事实核对继续由运营者决定。

## 1. 工作流目标

系统只解决运营者的两类核心工作：

1. 发现并写一篇值得写的新文章。
2. 判断并更新一篇确实需要更新的旧文章。

用户看到的流程只有两个阶段：

```text
第一阶段：关键词与主题调研
内部数据 + 外部调研 + 主题图谱
                ↓
每栏优先展示 2 篇；其余最终候选按标题折叠保留
                ↓
第二阶段：文章制作
专项素材调研 → 大纲与链接方案 → 草稿/修改稿 → 自动自审
                ↓
可直接复制到 CMS 的交付包
```

### 1.1 用户实际看到的五步

1. 数据导入：GSC 通过只读 OAuth 一键同步；Blog JSON 和 Product JSON 仍由运营者手工导入。
2. 主题调研：显式使用外部 API，只显示运行概况。
3. 文章建议：旧文左栏、新文右栏，统一做执行/跳过/不再推荐决定。
4. 文章制作：完成修改稿或新文章 CMS 八字段，发布后退出当前页。
5. 主题图谱：只显示真实导入内容的覆盖，不显示候选或计划。

“2 新 + 2 旧”只表示每栏直接展开的优先建议数量，不是每轮上限或配额。其余最终候选仍在同一栏逐条折叠显示；任何一类没有合格项时允许为 0，不能降低门槛凑卡片。

## 2. 第一阶段：关键词与主题调研（已确认）

### 2.1 三类输入

#### 内部数据

- 已导入的 GSC 查询、页面、日期、设备、国家和搜索外观数据。
- 已发布文章及其 title、slug、summary、正文、标签和链接。
- 产品资料。
- 历史分析、接受、拒绝、延后、完成和效果记录。

#### 外部调研

- Google Suggest、PAA 和时点 SERP。
- 用户痛点、论坛、社区和真实问句。
- 竞品覆盖、内容类型和切入角度。
- 官方文档、标准、法规、研究和产品事实。
- 新受众、新场景、生命周期、故障、限制、决策标准、技术变化和法规变化。

这些来源用于发现和验证候选，不直接等于搜索量、排名或本站查询事实。论坛和 AI 摘要只能发现线索；重要事实必须回到可复核原始来源。

#### 主题图谱

- 保存规范主题、别名、主父级和跨分支关联。
- 显式关联已有文章及其主要/辅助覆盖角色。
- 记住已经接受、拒绝、延后、完成或合并的主题身份。
- 判断某个方向是已覆盖、值得扩展，还是当前没有机会。

### 2.2 三个相互独立的调研入口

#### A. GSC 信号入口

用于发现旧文章表现问题，也可以提供新主题线索。查询与页面归属仍必须来自联合数据或人工明确复核，不能用标题相似度冒充事实。

#### B. 主题图谱缺口入口

当某个已确认分支存在真实用户任务，但没有合格文章覆盖时，可以直接围绕该缺口做外部调研，不要求先出现 GSC 查询。

#### C. 边界扩展入口

当 GSC 信号弱、已知缺口也少时，系统不再重复搜索宽泛词，而是选取一个现有分支，按尚未充分研究的扩展维度寻找新的真实问题。

选择顺序不是永久固定的。每轮可以同时扫描三类入口；某一路没有信号时，把剩余调研预算转给其他入口，而不是停止整个流程。

三个入口生成的候选，其主题、标题、意图、受众和角度等语义字段统一使用自然英文。候选必须依次与当前 CMS、历史候选和本轮已接受候选做规范主题去重；主题图谱缺口和边界扩展本身不强制要求查询—页面证据，只有把某个 GSC 查询归因给旧页面时才需要联合数据。

发现阶段宽进，进入新文章建议的硬阻断只有活动 CMS 的同主意图或正文已覆盖子题。需求、
范围、材料强度、关系不确定和弱信号继续单独显示，供运营者判断价值与写作准备度；它们不在
主题发现阶段静默删除一个未重复方向。Tavily、论坛和社媒只能提供公开市场代理语言，不能
冒充本站反馈或搜索需求；Firecrawl 页面采集用于核对来源和准备写作材料。

`multi_source_topic_research 0.15.0` 恢复十二类开放入口，覆盖现象、受众、任务、环境、
生命周期、故障、决策、生态、安全/规则、交易、变化与 emerging。自动选中的图谱分支只给
旧 Plan 任务卡提供上下文，不会收窄全部来源查询。所有来源支持且未被 CMS 重复门拦截的种子
继续显示，只选择 5 个消耗后续 API 深挖；末端合并同页面职责的换说法，并与已有候选池去重。
`input_refs` 必须能从来源观察追溯到资料查询和页面正文。新文章重复检查只对照活动博客正文；
产品规格只参与产品/内链和主题图谱判断。

### 2.3 边界扩展调研怎样工作

#### 触发条件

任一条件满足即可进入：

- 当前没有合格 GSC 主题信号。
- 图谱中已知未覆盖节点不足以形成候选。
- 最近几轮只重复发现已有主题、别名或已拒绝项。
- 运营者在主题树节点点击“从这个方向继续调研”。
- 运营者在“暂无合格机会”页面点击“继续外部调研”。

#### 调研前先形成分支档案

分支档案包含：

- 分支边界和已确认受众。
- 已有主要文章主题。
- 常见辅助知识，例如安全、功率、波长和法规说明。
- 已接受、拒绝、延后和完成的主题。
- 过去使用过的搜索查询、来源、结果和无结果记录。
- 关联产品、用户痛点和最近出现的新信号。

#### 七个扩展维度

系统按“分支 × 维度”轮换研究，优先选择从未研究或已经过期的格子：

1. 新受众与角色：还有谁面临不同的问题？区分实际使用者、购买或决策者、经验水平和职责。
2. 新场景、目标与生命周期：用户要获得什么具体结果？使用前、使用中、使用后分别有什么任务？哪些地点、时间或环境条件会改变问题？
3. 新故障、限制与替代：什么情况下不能用、效果不好、容易损坏、容易误用或风险过高？什么时候不该使用，并应改用什么？
4. 新决策与验证标准：用户选择、比较或购买时真正判断什么？怎样核实规格、测量、认证、总成本和购买后风险？
5. 新产品、技术、兼容与生态变化：产品、配件、供电、安装和其他关联组件出现了什么变化或兼容问题？
6. 新法规、安全、地区和行业变化：适用地区、使用地点、生效日期或行业规则发生了什么变化？
7. 相邻但仍属于当前网站边界的问题：问题可以涉及替代或配套方案，但用户目标仍须与激光笔站点的既定目的直接相关。

这些维度只负责生成研究问题，不能机械做笛卡尔组合，也不能把每个组合直接变成文章标题。

#### 横向筛选器

下列信息可以作用于每个扩展维度，但不增加新的一级维度：

- 搜索意图：了解、操作、购买、验证或故障排查。
- 地区、语言和司法辖区。
- 使用者经验、职责和决策角色。
- 季节、天气、距离、光线以及室内/室外等使用条件。
- 内容形式：指南、比较、故障排查或法规说明。

横向筛选器只用于细化研究问题、检索口径和适用边界，不能单独生成图谱节点或文章候选。同一个核心用户问题在不同筛选条件下仍可能是同一个主题。

#### 外部来源分工

- Google Suggest/PAA：发现用户措辞和问题，不证明搜索量。
- SERP：判断当前搜索意图、内容类型和已有竞争结果。
- 用户痛点/论坛：发现实际任务、顾虑和失败情形，不单独证明技术事实。
- 竞品内容：检查共同覆盖和遗漏角度，不复制正文，也不把竞品声明自动当事实。
- 官方/标准/研究：核实安全、法规、技术和产品事实。
- Tavily：发现来源。
- Firecrawl：采集选定公开网页。
- SerpAPI：采集固定口径 SERP/Trends。
- AI：归纳已经保存的证据，不创造来源、搜索量或需求事实。

#### 预算与停止条件

运营者确认的每轮可设置范围为：

- SerpAPI：0–10。
- Firecrawl：0–10。
- Tavily：0–20。
- AI 整理：0–20。

预算是最大真实请求数，不是必须用完的次数。命中缓存不重复计费；当已经得到足够的独立候选、剩余方向只产生重复结果，或来源质量不足时应提前停止。

#### 调研记忆

每次运行保存分支、维度、横向筛选器快照、查询、参数哈希、来源 URL、发现的规范主题、重复匹配、无结果结论和时间。下一轮默认跳过相同口径和没有新鲜度理由的重复搜索。

只要手持激光笔仍是核心对象，新受众、用途和细化任务可以进入折叠候选池，由运营者人工判断品牌适配。若核心对象已变成激光水平仪、切割/雕刻机或激光瞄具，只保留偏移诊断或 raw lead，不得冒充手持激光笔主题。

### 2.4 文章主题与通用知识

每篇文章最多关联一个“主要文章主题”，同时可以关联多个“辅助知识主题”。

主要主题由页面的核心用户任务决定，判断依据包括 title、H1、slug、开头承诺、正文主要篇幅和结论。H1/H2 层级是重要信号，但不能单独决定主题身份。

例如：

- `How Laser Pointer Wavelength Affects Visibility` 的主要主题就是“波长与可见性”。
- `Best Laser Pointer for Night Fishing` 中的波长、功率和安全 H2 通常是辅助知识，主要主题仍是“夜间钓鱼选择激光笔”。

安全、波长、功率、法规和电池等内容经常出现在多篇文章中。作为辅助知识时，不占用新的文章主题名额，也不主导重复判断；当页面本身主要回答这些问题时，它们恢复为主要主题并正常参与查重。

### 2.5 候选资格与输出

#### 旧文章候选

只有存在真实更新理由才进入建议，例如持续表现变化、搜索外观不匹配、事实过期、搜索意图变化、正文缺失关键答案或链接失效。年龄本身不是更新理由。

#### 新文章候选

发现期要求主题承担一个可辨认的主要用户意图，并通过图谱/CMS 主意图和正文覆盖检查；只有
`same_intent` 或 `covered_subtopic` 阻断新建。需求信号、品牌适配和可靠写作材料作为可见诊断
与制作前准备度，允许运营者从较大的未重复主题池中人工挑选。安全、法规、具体商家或产品事实
在制作前仍必须取得相应官方、一手或可追溯来源。

通过门槛后，每轮最多输出 2 篇旧文章和 2 篇新文章。旧文章名额与新文章名额互不强行填补。

### 2.6 信号不足时的用户选择

工作台显示“本轮暂无合格机会”或实际不足的数量，并提供：

1. `继续外部调研`：系统自动研究下一批未充分覆盖的分支/维度，不重复上一轮查询。
2. `打开主题图谱`：运营者选择节点并点击“从这个方向继续调研”。
3. `等待新信号`：等待新的 GSC、产品、法规、技术、季节或用户问题。

连续调研没有新发现，只能说明当前范围暂时没有合格机会，不能声称整个主题永久穷尽。

### 2.7 用户需要操作的状态

运营者只需要三个决定：

- 要做。
- 不再推荐。
- 暂时跳过。

“已有文章、部分覆盖、待证据、已完成、暂时饱和”等属于系统内部事实或派生状态，不要求运营者逐项维护。主题树主视图只需显示“已有文章、值得扩展、暂无机会”。

## 3. 第二阶段：文章制作（基础流程已实现）

第一阶段回答“做什么”，第二阶段回答“怎样把这篇文章做好”。两阶段的外部调研目的不同：第一阶段发现主题，第二阶段只为已经接受的具体文章收集写作证据和素材。

0.10.1 的新文章先用已有存证材料生成无需 API/AI 的素材清单，经运营者确认后再依次完成文章方案、完整初稿、编辑定稿和确定性检查；旧文章仍按修改幅度生成并锁定 Slug。

### 3.1 用户看到的流程

用户接受建议后，不再进入六步通用清单。新旧文章在同一张任务卡继续完成：

- 旧文章：先查看系统整理的现有素材，再生成修改稿。
- 新文章：先查看系统整理的现有素材，再选择 `现有素材够用，开始写作` 或粘贴手工搜索材料。

系统内部可以执行多步，但用户只处理必要决定：

```text
旧文章：查看素材 → 可选手工补充 → 确认写作 → 核对 → 我已发布
新文章：查看素材 → 可选手工补充 → 确认写作 → 核对 → 我已发布
```

素材分类、文章方案、调用次数和自审结果都可展开查看，不要求逐项勾选。
发布后点击“我已发布”，任务移入“观察与历史”，不再堆在当前任务中。

### 3.2 专项素材调研包（目标边界）

系统先整理任务已经保存的内部与外部材料，这一步不调用搜索 API，也不调用 AI：

- A：用户痛点。
- C/D：可用案例与本篇能够增加的新信息。
- E/F：权威来源与竞品覆盖/缺口。
- G/H：真实搜索问题与作者、实测、第一手经验边界。

市场规模、价格、竞品报价和零售商比较不进入素材包。

关键材料门槛为 A、E、G 均有内容，至少两个可追溯来源；安全、法规、技术参数等敏感主题还必须有官方或研究来源。

若材料不足或运营者希望补强，任务卡会给出本篇专用搜索提示词。运营者把结果粘贴回来即可；系统将原文保存为不可变素材快照，不调用外部 API 或 AI，重复粘贴也不会重复写入。

只有运营者明确确认“现有素材够用”后才开始写作。系统不能在确认前偷偷生成文章。

每篇文章单独建立并保留可审计素材包，至少包含：

- 目标读者、核心问题、搜索意图和页面职责。
- 一句话核心答案和文章需要提供的独特价值。
- 当前 SERP 内容类型、共同覆盖和可验证缺口。
- 用户痛点和真实问句。
- 官方、一手、研究和行业来源。
- 产品规格及其真实来源。
- 事实声明清单：每个数字、法规、安全和性能结论对应来源。
- 允许使用的案例、图片、表格或实验；没有真实材料时不得编造。
- 主要主题、辅助知识和与已有文章的边界。
- 建议内链、回溯内链和外部引用位置。

竞品页面主要用于理解意图、结构和遗漏，不作为事实的默认来源。法律、安全、技术参数和产品性能优先回到官方、标准、研究或可复核一手材料。

### 3.3 大纲不是固定模板

系统先确定“读者完成什么任务”，再选择结构。可参考但不能强制所有文章使用同一框架：

- 解释型：直接答案 → 原理/因素 → 实际影响 → 限制与安全 → 读者决策。
- How-to：前提与安全 → 操作步骤 → 成功判断 → 故障排查 → 后续维护。
- 购买/比较/评测：决策标准 → 证据和比较方法 → 选项差异 → 适合谁/不适合谁 → 权衡与结论。
- 法规/安全：适用地区和日期 → 官方规则 → 允许/禁止事项 → 实际风险控制 → 来源与更新条件。

为避免模型忽略必要组件，采用运营者确认的稳定交付基线：

- Pillar Page：2500–4000 个英文词。
- Cluster Content：1200–2500 个英文词。
- Product Roundup：2000–3500 个英文词。
- 导语 150–250 个英文词，直接说明问题与文章价值。
- Key Takeaways 3–5 条。
- 正文通常 4–7 个主要 H2；每段不超过 4 句。
- 结论 150–200 个英文词；FAQ 3–4 问，并生成与可见 FAQ 一致的 FAQPage JSON-LD。

这些是本站的编辑与稳定输出规格，不是 Google 排名公式。结构、标题和论证仍必须根据本篇用户任务变化，不能为了凑字数填充重复内容。

### 3.4 旧文章的三种交付

所有旧文章都保持原 slug；修改后的主要意图不能偏离 URL 和原页面职责。若必须改变主要意图，应改为新文章候选，而不是硬改旧 URL。

页面级 GSC 信号默认只表示“需要诊断”。制作旧文章前，程序会再次检查当前 CMS 快照、已通过的机会门槛、已确认的 A/E/G 素材及至少两个可追溯来源、当前窗口的查询—页面联合证据；点击下滑或保护类判断还必须有上一窗口的联合证据。缺少其中任一项时不得调用 AI，也不得生成重写稿。

旧文章通常使用两次相互独立的 AI 调用：第一次按允许的修改类型生成草稿，第二次以编辑身份审查并定稿。程序随后强制检查 slug 与主题锁定、自然英文、修改范围、站内链接白名单、URL 不重复、空泛填充和虚构第一人称经验；未通过时只在调用上限内定向修订，最终仍未通过则不保存交付包。

#### A. 标题/描述或极小修改

交付：

- 需要替换的 Title、SEO Title、SEO Description。
- 精确到段落的替换文字。
- 需要增加、删除或修正的链接。
- 不输出无关的整篇重写稿。

#### B. 局部内容更新

交付：

- 保留部分与修改理由。
- 完整替换区块及插入位置。
- 已核实的新事实、来源和链接。
- 修改后的文章完整预览，避免局部复制后上下文断裂。

#### C. 原主题重写

交付完整 CMS 字段和完整 Markdown，但 slug 固定不变。系统先保留原文中仍准确、有效和有价值的内容，再重构全文，不能为了“去 AI 味”或新鲜度无差别改写所有段落。

只有内容实质改变时才建议更新页面日期；不能仅换措辞或年份制造新鲜感。

### 3.5 新文章制作

新文章通过资格门槛后，系统依次完成：

1. 程序整理已有素材，不消耗 API/AI。
2. 运营者决定是否补充手工搜索素材。
3. 运营者确认素材够用。
4. AI 第一次调用形成文章专属方案、来源与链接计划。
5. AI 第二次调用按已确认材料生成完整初稿。
6. AI 第三次调用以编辑身份完成定稿。
7. 程序检查字段、结构、篇幅、FAQ、链接、重复和虚构风险；只有不通过时才请求 AI 修订。
8. 生成 CMS 八字段、链接清单、来源清单和自审结果。

正常新文章使用 3 次 AI；旧文章通常使用 2 次（草稿 + 独立编辑审查）。每篇文章的 AI 调用上限可在设置页配置为 3–10 次，它是防止无限返工的保险丝，不是必须用满的额度，也不与外部调研预算混算。

写作过程中发现主题与已有文章实质相同，应停止新稿并转为旧文章更新建议，不能靠换标题继续发布。

### 3.6 内链与外链

#### 内链

- 主题图谱先找候选页面，再读取实际正文确认是否自然相关。
- 同时规划新/旧文章链向哪些站内页面，以及哪些已有文章应回链到本次页面。
- 锚文本简洁、描述目标页并适合当前句子，避免 `click here`、堆关键词和批量复制同一锚文本。
- 删除或修正失效、错误、重复和与当前意图无关的旧链接。
- 根据文章实际篇幅动态规划：相关博客内链约每 1000 词 1 条；商业文章的产品内链约每 1300 词 1 条。
- 上述数量是规划目标，不是硬塞配额；候选不足或上下文不自然时允许更少或为 0。
- 系统从全站索引先筛最多 12 个相关候选，只有大纲批准的 URL 才能进入正文，同一 URL 只出现一次。
- 重要页面至少应从另一个相关页面获得可抓取的站内链接，避免孤立页面。

#### 外链

- 在事实声明附近链接最接近的一手或权威来源，让读者能核实结论。
- 权威外链约每 800 词 1 条，并随需要核实的声明数量调整。
- 只能使用已存证且真正支持相邻声明的 URL；素材不足时停止或说明，不自行补造 URL，也不为达到数量重复引用。
- 链接必须嵌在支持对应声明的正文句子中，导语和结论不新增链接。
- 记录最终 URL、标题、来源类型、访问日期和它支持的具体声明。
- 付费/联盟链接按站点能力使用 `sponsored` 或 `nofollow`；普通可信引用不应全部加 `nofollow`。
- 链接到竞品不是默认禁止，但只有当它确实是最佳原始来源或对读者有必要时才使用。

### 3.7 三种“重复”必须分开

1. **文字重复**：大段相同或近似措辞。可通过文本相似度和人工审阅发现；合理引用要标来源。
2. **意图重复/蚕食**：两个页面服务同一读者、回答同一主要问题并承诺同一结果。换文案不能解决，应优先更新、合并判断或停止新建。
3. **允许共享的辅助知识**：安全、波长、功率、法规等在不同文章中简要出现。查重时降低权重；需要完整解释时链接到主要文章。

正文相似度只能发现风险，不能单独决定蚕食。主要判断来自规范主题、页面职责、搜索意图、SERP、可用的 query→page 数据和全文边界。

### 3.8 “去 AI 味”改为编辑去模板化

目标不是欺骗 AI 检测器，而是让文章具体、可信、有本站自己的判断。系统不得把 AI 检测分数作为发布门槛，也不得用同义词改写器把旧文换一种说法。

编辑检查包括：

- 删除空泛开头、万能转折、重复总结和没有信息的形容词。
- 保留 Key Takeaways、FAQ 等稳定交付组件，但每篇的开头、H2、论证、问题和结尾必须服务本篇任务，不能复用同一套文案。
- 用本篇特有的事实、限制、比较标准和真实例子替代通用套话。
- 比较近期文章的开头、H2、CTA 和高频句式，标出跨文章模板复用。
- 允许句子和段落长度随信息变化，不为了“像人”故意加入错误。
- 不编造第一人称测试、作者资历、用户故事或独立评测。
- 只在真实使用 AI 且读者合理关心制作方式时，按站点政策提供准确说明。

### 3.9 自动自审

自审分为可确定检查和编辑判断，两类结果分开展示。

#### 可确定检查

- CMS 必填字段齐全，旧文章 slug 未改变。
- 标题、链接和 Markdown 格式有效。
- 每个数字、法规、安全、性能和产品规格声明能回到素材包来源。
- 引用 URL 可访问，锚文本非空，站内链接指向已知页面。
- 没有未知作者、虚构实测、伪造案例或来源。
- 与现有文章的大段文字相似风险、重复标题和重复元描述可见。

#### 编辑判断

- 是否直接并完整回答主要问题。
- 是否比搜索结果中的现有内容提供真实增量，而不是改写汇总。
- 大纲是否符合该文章类型，是否存在无关 H2 或遗漏关键步骤。
- 主要主题是否与已有页面冲突，辅助知识是否被误判为新主题。
- 每个链接是否真正帮助读者，产品推荐是否符合当前上下文。
- 文章是否准确表达“谁写、怎样获得信息、为什么写”，并避免虚构经验。
- 读者看完后是否仍必须重新搜索才能完成任务。

只有阻塞项通过后才生成“可交付”状态。系统可以提出修订稿，但发布仍由运营者人工完成。

### 3.10 CMS 交付字段

新文章和旧文章重写交付：

- Title
- Slug（旧文章固定不变）
- Summary
- Content (Markdown)
- Tags (comma separated)
- SEO Title
- SEO Description
- SEO Keywords

小修改只突出实际变化字段和精确替换区块，同时提供修改后预览。SEO Keywords 因 CMS 必填而生成，但不作为核心优化依据。

### 3.11 发布后

系统可由“我已发布”记录发布时间并把任务移入观察历史；7/28/56 天自动提醒和观察录入仍待增强。接受文章和生成草稿都不是效果证据。

## 4. 旧工作流审查结论

| 旧做法 | 处理 |
|---|---|
| research material pack、真实来源和审计简报 | 保留并结构化 |
| SERP 意图、竞品共同覆盖和差异角度 | 保留，但竞品不是默认事实源 |
| 用户痛点、真实问句、案例和权威引用分类 | 保留，增加证据等级和来源核验 |
| 新文章发布后寻找 1–3 个回溯内链位置 | 保留，改为图谱候选 + 正文确认 |
| 所有文章固定 APP、Key Takeaways、FAQ、视频和 CTA | 不照搬旧固定模板；保留 Key Takeaways 与 FAQ 的稳定组件，视频/CTA 不作为内容要求 |
| 固定 3000–5000 字或按类型硬定字数 | 改为三类文章的编辑范围；完整回答优先，范围不是排名因素 |
| 每 800/1000/1300 词强制一定数量链接 | 改为按篇幅动态规划的软目标；相关性不足时不强塞 |
| 主关键词必须进入 H1、前 100 词和至少两个 H2 | 降级为自然相关性检查，禁止关键词填塞 |
| FAQ Schema 每篇必加 | 仅与可见 FAQ 一致时生成；作为交付一致性，不承诺普通电商博客获得富媒体展示 |
| 化名作者、虚构“多年实测”或伪造第一人称经验 | 禁止；作者、实测和资历必须真实 |
| TF-IDF 单阈值决定蚕食，可人工 force | 改为风险提示；主题身份、意图和全文共同判断 |
| “Scrub 去 AI 水印”或 AI 检测器门控 | 取消；改为证据、原创增量和编辑去模板化 |
| 完成后删除素材包 | 取消；研究和来源记录应保留以便复核 |
