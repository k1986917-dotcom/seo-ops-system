# 系统架构

## 1. 总体结构

```text
┌──────────────────────────────┐
│ 浏览器：Dashboard / Top 3 / 导入 / 复盘 │
└──────────────┬───────────────┘
               │ HTTP
┌──────────────▼───────────────┐
│ FastAPI 应用层                              │
│ 路由 · 表单 · 权限边界 · 展示适配           │
└───────┬───────────┬─────────┘
        │           │
┌───────▼──────┐  ┌─▼────────────────┐
│ 确定性核心     │  │ 可选 AI Provider  │
│ 导入/规则/排序 │  │ 解释/brief/草稿   │
└───────┬──────┘  └──────────────────┘
        │
┌───────▼────────────────────────────┐
│ SQLite + 不可变文件快照              │
│ Evidence / Rules / Opportunities / Actions / Outcomes │
└────────────────────────────────────┘
```

## 2. 五个逻辑层

### 数据层

保存原始快照、哈希、导入批次和标准化记录。原始文件永不被清理。标准化失败不能破坏快照。

### 证据层

把 GSC 指标、CMS 内容、产品事实、人工输入和外部来源标成不同证据类型。每条证据保留来源、时间、直接性和局限。

### 规则层

规则包含：资格门槛、诊断条件、行动模板、证据要求、版本、理由、官方来源、复查日期和失败模式。

### 决策层

先执行 hard gates，再对合格机会排序，最后组合 Top 3。分数只用于比较，不声称是成功概率。

### 执行与学习层

把机会转成任务，交给 research/write 或人工编辑，记录实际改动、发布日期和后续观察。规则校准使用结果，不使用“用户点了接受”替代结果。

## 3. AI 边界

AI 通过 `services/ai.py` 的 Provider 接口接入。路由和规则模块不直接调用供应商 API。

输入给 AI 的内容必须包含稳定证据 ID；输出必须是结构化 JSON，并保留 provider、model、prompt hash、输入引用和运行时间。AI 输出属于 `interpretation`，永远不能写入原始 evidence 或覆盖 rule score。

## 4. 部署方式

第一版面向本机 WSL：

- 监听 `127.0.0.1:8787`。
- SQLite 与快照位于项目 `data/`。
- 用户通过浏览器操作。
- API Key 存在 `.env`，该文件被 Git 忽略。

后续若需要局域网或公网访问，再单独增加身份认证、HTTPS、备份和密钥管理。第一版不默认暴露到公网。
