# 系统架构

## 1. 总体结构

```text
┌──────────────────────────────────────┐
│ 浏览器：工作台 / 导入 / 机会 / 方法 / 设置 │
└──────────────────┬───────────────────┘
                   │ HTTP（localhost）
┌──────────────────▼───────────────────┐
│ FastAPI 应用层：路由 · 表单 · 本机边界 · 展示 │
└───────┬───────────────────┬──────────┘
        │                   │
┌───────▼────────┐  ┌───────▼──────────────────┐
│ 确定性核心       │  │ services/ 外部适配层       │
│ 导入/质量/门槛/排序│  │ SerpAPI/Firecrawl/Tavily/AI │
└───────┬────────┘  └─────────────┬────────────┘
        │                         │
┌───────▼─────────────────────────▼────────────┐
│ SQLite（派生状态）+ 不可变文件快照 + 本地 .env │
│ Evidence / Rules / Opportunities / Actions / Outcomes │
└──────────────────────────────────────────────┘
```

## 2. 五个逻辑层

### 数据层

保存原始快照、哈希、导入批次和标准化记录。原始文件永不被清理。外部执行层完成后，供应商响应也必须进入不可变快照，而不是只保存 AI 摘要。

### 证据与质量层

GSC、CMS、SERP、Trends、网页内容和研究线索标成不同证据类型。每条证据保留来源、参数、时间、直接性和局限。`services/data_quality.py` 先检查独立窗口与官方 GSC 异常。

### 规则层

规则包含资格门槛、诊断条件、行动模板、证据要求、版本、理由、官方来源、复查日期和失败模式。`gsc_signal_stability 0.2.0` 会改变置信权重或把曝光相关候选降为补证据。

### 决策层

先执行 hard gates，再对合格机会排序，最后组合 Top 3。分数只用于比较，不声称是成功概率。当前公开入口在 `opportunities/quality_engine.py`，复用已验证的基础候选生成器后追加数据质量门槛。

### 执行与学习层

把机会转成任务，交给 research/write 或人工编辑，记录实际改动、发布日期和后续观察。规则校准使用结果，不使用“用户点了接受”替代结果。

## 3. 外部来源与 AI 边界

- `services/external_sources.py` 集中连接能力与来源角色。
- `services/settings_store.py` 负责本地设置的验证、原子写入和运行时更新。
- `services/ai.py` 只接收稳定 evidence ID，输出属于 interpretation。
- 路由、模板和规则不直接拼供应商 HTTP 请求。
- 连接测试与数据采集分开；连接成功不产生证据，也不改变分数。
- 下一版本应新增 `external_runs`，记录 provider、purpose、参数、成本、响应快照、哈希和 evidence ID。

## 4. 凭据边界

- API Key 只在项目根 `.env` 与后端进程环境中存在。
- `.env` 权限为 `0600`，被 Git 忽略；临时 `.env.tmp` 也被忽略并以原子替换完成写入。
- 密钥不写入 SQLite、HTML、重定向消息或异常日志。
- 设置表单拒绝非 localhost Origin。
- `.env` 未加密，只适用于当前单人本机 WSL。

## 5. 数据库迁移

- v1：站点、导入、GSC、内容、规则、机会、行动、观察和 AI 运行。
- v2：`source_connections`，只保存连接状态、时间、白名单明细和安全错误，不保存凭据。

启动时按 `PRAGMA user_version` 增量迁移，用户不需要删除现有数据库。

## 6. 部署方式

第一版监听 `127.0.0.1:8787`。SQLite 与快照位于 `data/`，用户通过浏览器操作。若需要局域网或公网访问，必须另行增加身份认证、HTTPS、备份、CSRF 完整防护和真正的密钥管理。
