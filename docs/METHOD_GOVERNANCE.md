# 方法治理：怎样保证系统科学、权威且可更新

## 1. “科学”在本项目中的含义

本系统不宣称存在一条万能 SEO 公式。方法质量来自：

- 数据来源与局限可见。
- 推断链可以复查。
- 经验阈值明确标记并可配置。
- 决策前有资格与数据质量门槛。
- 执行后有预先定义的观察指标。
- 规则可以根据真实结果升级、降级或废弃。

## 2. 证据等级

| 等级 | 类型 | 用途 |
|---|---|---|
| A | 站点第一方原始数据：GSC、CMS、未来订单数据 | 判断本站实际状态 |
| B | 搜索引擎/平台官方文档与报告 | 确认政策、字段含义、异常和能力边界 |
| C | 可复核的一手网页、SERP、法规、研究或产品事实 | 验证具体主题和竞争环境 |
| D | 独立可靠的行业研究 | 提供外部基准或候选假设 |
| E | 工具估算、AI 搜索摘要、论坛、经验规则 | 发现线索，不单独支持高置信决策 |

多个 E 级来源不自动等于 A/B 级证据。来源数量、独立性、质量、直接性和新鲜度分别评价。同一网页被 Tavily 找到、Firecrawl 抓取、AI 总结，仍然主要是一份底层证据。

## 3. 数据源角色

- GSC：本站搜索表现，但受聚合、顶部行、不完整数据和官方日志异常限制。
- SerpAPI：指定市场与设备下的时点 SERP，不代表稳定搜索量。
- Google Trends：相对兴趣与季节性，不代表绝对量。
- Firecrawl：页面公开内容，不代表需求、排名、权威或真实性。
- Tavily：资料发现，返回结果必须回到原始来源核验。
- AI：证据综合与语言生成，不是外部事实源。

详细矩阵见 `docs/EXTERNAL_DATA_SOURCES.md`。

## 4. 决策结构

### 阶段零：数据质量门槛

在内容机会之前先回答：

- 数据是否已经完整，日期是否命中官方异常？
- 是否至少有三个独立观察窗口？
- 高曝光零点击是否跨至少两个完整窗口持续？
- 是否拆分了查询、页面、国家、设备与搜索外观？
- 是否需要 SERP/Trends 来区分结果页变化与季节性？

观察窗口不足时降低置信权重；命中官方异常时，曝光相关项只允许输出补证据。
“当前用于出机会”和“可作为可信历史窗口”必须分开：当前机会只读唯一活动批次；稳定性可累计后续正常导入，但运营者已确认异常的历史批次不得计数。


### 阶段一：资格门槛

- 证据是否足够支持“存在问题/机会”？
- 目标页面是否明确？
- 是否可能与现有内容严重重叠？
- 用户是否有权限执行动作？
- 是否存在安全、法律、品牌或删除风险？

不通过时输出“补证据”“暂不做”或风险说明，不进入常规排序。

### 阶段二：排序

第一版采用冷启动排序：

`priority = strength × confidence_weight ÷ effort`

- `strength` 是站内相对强度，不是流量预测。
- `confidence_weight` 来源于证据质量、稳定性与直接性，不是来源个数。
- `effort` 是单人运营的相对工作量。

分数必须同时显示分项和方法版本。

### 阶段三：最多 2 篇旧文章 + 2 篇新文章

- 旧文章席位只接收通过资格门槛的博客更新任务，按当前证据优先级最多选择 2 篇；产品页和纯诊断线索不占席位。
- 新文章席位只接收通过重复/边界检查且由运营者确认“值得做”的研究主题，最多选择 2 篇。
- 同一目标不能重复占位；已接受或制作中的有效任务可以保留在当前组合。
- 任何一类没有合格项时允许为 0，禁止为填满四张卡降低门槛。分析线索保留在折叠诊断区，不进入执行。

### 阶段四：外部补证据与新文章候选

- 针对已有页面做查询级 SERP/Trends 补证据时，只能使用明确的 GSC 查询；页面标题、slug 或关键词重合不能被猜成查询。该限制不阻止图谱缺口或已确认分支发起新主题调研。
- 外部调用必须由运营者点击触发，并记录固定国家、语言、设备、位置、时间范围、输入 evidence ID、参数哈希和用量。
- 相同口径 24 小时内复用，避免重复消费；复用同一快照不增加来源独立性。
- 日常界面遵守“一个对象只有一个页面”：导入批次只在数据导入，调研概况只在主题调研，待决定建议只在文章建议，制作任务只在文章制作，真实覆盖只在主题图谱。
- 研究候选被执行时不得创建图谱覆盖节点；只有 CMS 实际重新导入后才建立 article_topic。

- SERP 只证明采集时看到的结果，Trends 只证明归一化相对兴趣；二者不修改 GSC 事实和原机会分数。
- 新文章候选可以来自 GSC 查询、主题图谱缺口或边界扩展。通过门槛至少需要独立主要意图、边界内资格、CMS/全文覆盖检查、可解释的需求或变化证据，以及足以完成写作的可靠材料；不再强制每个新主题先有 GSC 查询。
- SERP 已有本站页面服务同一主要意图时，新文章候选应停止并转向检查旧文章。CMS 标题/Slug/SEO 字段用于判断主主题身份，摘要和 Markdown 小标题用于判断结构化正文覆盖；达到已登记门槛时可以阻断重复新建，但这仍是程序推断，不能声称某个 GSC 查询属于该页面。
- 第一阶段即使门槛通过，也只生成文章建议。第二阶段由运营者启动专项调研与文章制作，任何阶段都不自动发布。

### 阶段五：预算化多来源主题调研

- 调研是独立、显式的运行，不随第一方分析自动调用。种子可以来自明确 GSC 信号、主题图谱缺口、边界扩展或上一轮未消费的来源观察；无 GSC 种子的开放调度同时搜索现象、受众、任务、环境、生命周期、故障、决策、生态、安全/规则、交易、变化与 emerging 十二类入口，并混合 PAA/相关搜索、论坛/社区、评价、社媒/视频、商业/竞争候选页和官方/参考页的公开语言。十二类是覆盖检查表，不是主题白名单；自动选中的图谱分支只给旧 Plan 任务卡提供上下文，不能被拼进全部入口形成隐性收口。来源 URL、摘录和 evidence ID 组成可审计种子；来源观察是市场代理，绝不是本站第一方反馈、需求事实或产品适配证明。旧 Plan 的版本化“角色 × 任务 × 条件”任务卡与独立问题链继续作为精确前沿和补足，不要求每个新方向都硬套该形状。任务卡只做 CMS 同主意图/正文覆盖预筛；需求、范围、材料与弱信号均不阻断发现。每个供应商的预算是本轮最大真实请求数，并受代码硬上限保护。
- 语义簇和大方向清单只帮助调度与覆盖，不是关键词白名单。若立即上一条已完成运行明显集中在一个簇，下一轮只对该簇软冷却一次；核心/相邻/偏移对象也只影响排序。没有其他可用种子时，冷却或相邻方向仍可进入调研，绝不成为永久禁词或资格门。核心对象判断必须以来源摘录/标题为准，生成查询中的 `laser pointer` 不能把相邻产品升级为核心。
- 24 小时缓存复用不扣真实请求预算，也不增加证据独立性；剩余额度可以继续覆盖研究计划中的下一个未采集种子或扩展维度。
- SerpAPI 提供 SERP/Trends，Tavily 只发现来源，Firecrawl 只采集公开页面，AI 只整理本轮已存证材料。工具角色不能互换。
- 新主题首先是外部发现假设，不进入原机会分数。来源支持且未被当前 CMS 同主意图/正文覆盖拦截的种子不设目标数量并全部留在折叠候选池；从中选择 5 个继续调用 SERP、资料发现、页面采集和 AI，只是深挖额度控制。末端按主要页面职责合并同意图换说法，并与已有候选池去重；同方向但任务、症状、决策、受众、地区、条件或结果不同的细化主题继续保留。调研页只展示运行概况；文章建议页每栏直接突出 2 项，其他最终候选逐条折叠保留。原始来源线索自动续入种子池，不是人工选择项。
- 指定主题分支发起的调研，候选必须与该分支保持最低词项相关性；偏离方向的问题可作为外部材料保存，但不得进入本轮文章候选。该门槛只防明显漂移，不替代人工意图判断。
- AI 引用必须归一化到本轮完整 evidence ID。只有唯一可解析的缩写/数字序号可以接受；歧义、未知、伪造引用和没有 ID 的事实必须丢弃。
- API 数量增加通常扩大覆盖，不自动提高置信度。可信度仍取决于证据等级、独立性、直接性和新鲜度。
- 运营者确认的可设置范围为 SerpAPI 0–10、Firecrawl 0–10、Tavily 0–20、AI 0–20；这是每轮上限，不是必须用完的次数。
- 边界扩展保持七个一级维度：受众/角色，场景/目标/生命周期，故障/限制/替代，决策/验证，产品/技术/兼容，法规/安全/地区，以及相邻站内问题。内部检查项可以补全，但不机械组合标题。
- 搜索意图、地区/语言、经验角色、季节/环境条件和内容形式是横向筛选器，只细化研究口径和适用边界，不能单独生成图谱节点或文章候选。
- 每次运行保存分支、扩展维度、横向筛选器快照、查询、来源、发现概念、重复匹配和无结果记录；下一轮先查历史，避免重复搜索和重复推荐。

### 阶段六：主题图谱与饱和判断

- 先建立少量稳定主干，再随真实搜索信号、用户问题和研究证据逐步扩展，不预先制造 100–200 个文章任务。
- 主题身份按用户问题、搜索意图和页面职责判断；不同措辞可以归入同一概念，关键词差异不能自动生成新文章。
- 每篇文章最多有一个主要文章主题，同时可关联多个辅助知识主题。安全、波长、功率等辅助内容不主导重复判断；当它们是页面主要问题时正常作为主要主题。
- 每个概念只有一个主父级用于树状展示，跨场景关系用 related 关联保存。
- 新发现先规范化并检查已有主题、文章覆盖和历史决定。已确认边界内的新意图可以进入资格判断；只有全新受众、明显不同用途或站点目的变化才请求边界确认。
- “要做、不再推荐、暂时跳过”及合并历史都是去重记忆，后续发现必须先检查；更细内部状态不要求运营者维护。
- 饱和按分支判断；没有合格项时可以继续外部调研、从图谱指定方向或等待新的 GSC、产品、法规、技术和用户问题信号。
- 人工可选择“从这个方向继续调研”、移动建议父级或标记边界，但日常使用不要求维护整张图。

### 阶段七：文章制作（基础已实现）

- 只有运营者接受文章建议后才进入制作。新文章先由程序整理已有素材，不调用搜索 API 或 AI；运营者明确确认后才允许写作。
- 素材清单按 A、C–H 显示用户痛点、案例、信息增量、权威来源、竞品、真实问题和经验边界；不收集市场规模、价格或竞品报价。A、E、G、至少两个来源及敏感主题的一手权威来源属于阻塞门槛。
- 运营者可先用系统生成的专用提示词手工搜索并粘贴材料；原文保存为不可变快照，重复内容幂等，不把 AI 摘要冒充原始来源。
- 每篇文章保留意图、页面职责、SERP、用户痛点、事实声明、原始来源、产品事实、图谱边界和链接计划组成的素材包。
- 大纲按解释、How-to、购买/比较/评测、法规/安全等任务选择，不能把同一模板套给所有文章。
- 文章类型采用运营者确认的编辑范围：Pillar 2500–4000、Cluster 1200–2500、Product Roundup 2000–3500 个英文词。这是稳定输出规格，不是 Google 排名规则。
- 稳定组件为 150–250 词导语、3–5 条 Key Takeaways、4–7 个主要 H2、150–200 词结论和 3–4 个可见 FAQ；JSON-LD 必须与 FAQ 一致。它们是编辑稳定性要求，不得成为填充篇幅的模板。
- 内链、产品链接和权威外链分别按约 1000/1300/800 词动态规划，但相关性与可追溯性优先；没有合格候选时不得为达到数量强塞链接。
- 新文章正常调用 AI 3 次：文章方案、完整初稿、编辑定稿。确定性检查失败时才修订；每篇上限由设置页配置为 3–10 次，并与外部调研预算分开计算。
- GSC 驱动的旧文章在任何 AI 调用前必须有该页面当前 query + page 联合行；click-loss 还要求上一窗口联合行。页面汇总本身只产生诊断。
- 旧文章也必须确认同一份可追溯素材，并同时保留当前 query + page 联合证据；分为元数据/极小修改、局部更新和原主题重写，slug 永不修改，主要意图不能偏离原 URL。正常先起草、再独立编辑审校，只有阻塞项存在时才在上限内修订。
- 文章不得以市场规模、价格区间、零售商比较、折扣、排行榜、Quick Specs 或 CTA 填充篇幅；产品链接仅能服务于明确的读者任务。
- 调研候选和所有读者可见 CMS 字段使用英语；非英语候选、偏离所选分支、批次内重复、历史候选重复、CMS 主主题强重叠或结构化小标题已覆盖的子题在写入前阻断。
- SEO Title/Description 的常见字符区间仅作编辑建议，不作为 Google 排名规则或文章保存硬门槛。
- 重复检查分为文字重复、意图/页面职责重复和允许共享的辅助知识；换文案不能解决意图重复。
- “去 AI 味”采用事实增量、真实品牌语气和编辑去模板化；不使用 AI 检测分数，也不虚构作者、实测、案例或第一手经验。
- 最终交付 CMS 必填字段、修改说明和链接清单；自动检查通过不等于自动发布。

## 5. 规则登记

每条规则必须包含 `rule_key`、版本、规则类型、所需证据、条件、输出动作、采用理由、失败模式、来源 URL、生效日期、复查日期和状态。官方指南变更创建新版本，不能静默改变历史决策。

## 6. AI 治理

AI 输出必须：

- 只引用传入的 evidence ID。
- 把事实、推断和建议分开。
- 明确不确定性与缺失数据。
- 使用结构化格式。
- 保留模型、供应商、prompt hash 和输入引用。

模型升级不是方法升级。更换模型后用固定测试集回归验证事实约束、引用和输出结构。

## 7. 效果追踪

每个已执行动作至少记录目标 URL、动作类型、实际修改摘要、执行/发布日期、执行前基线、7/28/56 天观察，以及同期站点级、季节性、算法更新和数据异常干扰。

第一版不强求统计显著，但避免把一天或单一 28 天窗口当成结果。积累样本后再升级匹配页面、差分或时间序列方法。

接受机会和生成草稿都不是效果证据。0.5.0 在接受时冻结基线并建立文章制作任务，内部步骤只用于审计，不再要求运营者逐项操作；运营者仍须核对 CMS 修改并人工发布。取消普通任务不会删除证据或历史决定。

## 8. 当前官方方法基线

- Google 生成式 AI 搜索仍基于核心搜索与质量系统，不需要特殊 AI Schema 或重写整套内容。
- 重点是独特、有用、可靠、非同质化内容。
- 作者与第一手体验必须准确真实。
- 普通电商站点不把 FAQPage 富媒体结果当作默认收益。
- title 和 meta description 没有固定字符上限，以准确、独特、对用户有用为目标。
- Google 官方流量下降排查优先算法、技术、安全/垃圾内容、季节性和迁移，不使用“沙盒”作为自动诊断。

具体来源和复查日期进入 `rule_versions` 与外部数据源基线文档，不把一句话永久硬编码为规则。
